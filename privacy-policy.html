Noctron Launcher is an Android home screen replacement. It works offline and keeps your information on your own device. There are no accounts, no advertising, no analytics, no crash telemetry and no third-party tracking or advertising SDKs anywhere in the app.

What the app does not do

  • It does not create an account or ask for a sign-in.
  • It does not show ads and contains no advertising SDK or advertising ID access.
  • It does not use analytics, crash reporting, attribution or A/B testing services.
  • It does not sell, rent or share personal data with anyone.
  • It does not run an update check, heartbeat or remote-config fetch.

Network requests

The launcher makes network requests in exactly three situations, each tied to a feature you choose to use. All of them use HTTPS and none of them carry an account, device identifier or advertising identifier.

Outbound requests
Weather When the weather readout is enabled, the app sends your coarse latitude and longitude (rounded to four decimal places) and your chosen temperature unit to Open-Meteo at api.open-meteo.com. Location is only read if you granted the optional approximate-location permission; without it the request uses a fixed default coordinate. The returned temperature and weather code are cached on your device.
Search suggestions While you type in the command bar (from the second character), the text of your query is sent to Google (suggestqueries.google.com) or DuckDuckGo (duckduckgo.com) to fetch autocomplete suggestions, depending on your setting. You can switch this off in the launcher settings, after which no suggestion request is ever made. Suggestions are not stored.
Currency rates When you use the currency conversion command, the app fetches a public exchange-rate table from open.er-api.com. The request contains no user data at all; the rates are cached locally for a day.

Those three endpoints are the only destinations the app contacts. They are ordinary web services, subject to their own privacy policies (Open-Meteo, Google, DuckDuckGo, ExchangeRate-API); the launcher sends them nothing beyond what is listed above.

On-device permissions

The launcher asks for a few sensitive permissions because a home screen cannot do its job without them. In every case the data is read and processed on your device only — it is not transmitted, uploaded or shared.

Installed apps — QUERY_ALL_PACKAGES

Used to build the app list, search your apps and apply icon packs. Package names and labels are cached locally so the list opens instantly.

Contacts — READ_CONTACTS

Used while you search, so typing a name offers the matching contact and its phone number, email address or photo thumbnail. Contact data stays in memory for that search and is never written to storage.

Calendar — READ_CALENDAR

Used to show upcoming events in the header agenda. Events are read-only, held in memory, and only the calendars you select in settings are queried.

Usage access — PACKAGE_USAGE_STATS

Used to sort frequently used apps first. The app reads a weekly foreground-time summary and keeps it in memory only.

Files — Storage Access Framework

File search uses the system folder picker, so the launcher holds no storage permission. If you grant a folder, the app remembers that grant locally and searches file names inside it. It does not read file contents and does not touch anything outside the folder you picked.

Other permissions

  • INTERNET — the three requests described above.
  • POST_NOTIFICATIONS — lets the launcher post its single local "silent notifications are waiting" summary.
  • EXPAND_STATUS_BAR, app-widget hosting and REQUEST_DELETE_PACKAGES — open the notification shade, host home-screen widgets and show the system uninstall dialog.
  • SET_ALARM — hands alarms and timers to your clock app.

Notification access

If you enable notification access, the app reads the title, body text, package name and timestamp of notifications, solely to show them in the launcher's notification hub and to hold "silent" notifications until you ask to see them. This content is stored in the app's local database on your device and is never transmitted anywhere.

Backup: the launcher excludes that database (calakmwl_db) from Google Cloud backup through its data_extraction_rules.xml rules, so notification content is never copied to Google's servers. App settings (calakmwl_prefs — theme, layout and preference values, no message content) may be included in cloud backup according to your Android backup settings.

Accessibility service

The app's NoctronAccessibilityService exists for one purpose: to lock the screen (GLOBAL_ACTION_LOCK_SCREEN) when you use a lock-screen gesture. It does not read screen or window content, it does not inspect interface text, and it does not process accessibility events. You can disable it at any time in Android's accessibility settings; only the lock gesture stops working.

What is stored on your device

  • A local database with your home screen layout, folders, notes and tasks, plus the retained notification rows described above.
  • Preferences such as theme, icon style, gesture bindings and which calendars or search folder you picked.
  • Short-lived caches: the last weather reading and the daily currency rates.

Nothing in that list is uploaded by the launcher.

Deleting your data

Everything the launcher stores lives inside its own storage on your device. Clearing the app's storage (Settings → Apps → Noctron Launcher → Storage → Clear storage) or uninstalling the app removes all of it, including notes, layout and retained notifications. There is no server-side copy to delete. If Android's cloud backup is enabled, remove the launcher's backup entry in your Google backup settings to delete that copy as well.

Children's privacy

"Noctron Launcher is a general-purpose home screen app, not directed at children under 13, and does not knowingly collect or store personal data from children.
